# Stable Diffusion WebUI Forge

A Pinokio launcher for [Stable Diffusion WebUI Forge](https://github.com/lllyasviel/stable-diffusion-webui-forge) — a build on top of Stable Diffusion WebUI that optimizes resource management and speeds up inference, particularly on consumer GPUs.

The launcher installs Forge, downloads SDXL base and refiner, wires the shared model folders into Pinokio's drive so checkpoints and LoRAs are reused across apps, and starts the Web UI on an automatically assigned port.

## What you get

- Text-to-image and image-to-image generation via the Forge Web UI
- SDXL base 1.0 and refiner 1.0, downloaded during install
- Shared model storage — checkpoints, VAEs, LoRAs, embeddings, hypernetworks, upscalers and ControlNet models are symlinked to Pinokio's drive and shared with other launchers (ComfyUI, Fooocus, Automatic1111)
- Built-in ControlNet and the Forge legacy preprocessors

## Requirements

- An NVIDIA GPU is strongly recommended. Tested on an RTX 4090 Laptop (16GB VRAM) with SDXL base.
- Roughly 20GB of disk for the app, dependencies and the two SDXL checkpoints.

## Usage

Everything runs from the Pinokio sidebar. The menu changes with the app's state — it is generated by `pinokio.js`, which treats the app as installed once `app/venv` exists.

Before installing:

| Menu item | Script | What it does |
|---|---|---|
| **Install** | `install.js` | Clones Forge into `app/`, links the shared model folders, downloads SDXL base + refiner, installs all dependencies |
| **Update** | `update.json` | Pulls the latest launcher and app code |

Once installed:

| Menu item | Script | What it does |
|---|---|---|
| **Start** | `start.js` | Launches the Web UI (shown while stopped) |
| **Open Web UI** | — | Opens the running server; appears only once the URL has been published |
| **Terminal** | `start.js` | Shows the running server's console output |
| **Download Models** | — | Submenu of one-click model downloads (see below) |
| **Update** | `update.json` | Pulls the latest launcher and app code |
| **Reinstall** | `install.js` | Re-runs the installer over the existing checkout |
| **Reset** | `reset.json` | Removes the installed dependencies so you can start clean (shown only while stopped, with a confirmation prompt) |

Click **Install** first. When it finishes, click **Start**, then open the **Open Web UI** tab.

The port is assigned automatically at launch, so several apps can run side by side without conflicting. The chosen URL appears in the sidebar; it is not fixed at 7860.

### Download Models

The **Download Models** submenu fetches extra checkpoints straight into the shared model folders — SDXL, SDXL Turbo, SD 1.5, SD 2.1, LCM LoRA, and Stable Video Diffusion (base, XT, and XT 1.1). **Download by URL** takes an arbitrary link for anything not listed.

Because the model folders are symlinked into Pinokio's drive, anything downloaded here is also visible to other launchers such as ComfyUI, Fooocus and Automatic1111.

## API

Forge exposes the standard Automatic1111 `/sdapi/v1/*` REST API, but **it is disabled by default** — `create_api()` only runs when Forge is started with `--api` (`app/webui.py:57,116`). Without it every `/sdapi/v1/*` route returns 404.

### Enabling the API

Add `--api` to Forge's command line arguments, then restart from the Pinokio sidebar:

- **Windows** — edit `app/webui-user.bat`:
  ```bat
  set COMMANDLINE_ARGS=--no-download-sd-model --api
  ```
- **macOS / Linux** — edit `app/webui-user.sh` and uncomment/set:
  ```sh
  export COMMANDLINE_ARGS="--api"
  ```

Note that `app/` is created by the installer and is not tracked by this repository, so **Update** may overwrite these edits. Re-apply them if the API stops responding after an update.

To require credentials, add `--api-auth username:password`. To run the API with no Web UI at all, use `--nowebui`.

### Base URL

Every example below uses `http://127.0.0.1:PORT`. Substitute the port shown in the Pinokio sidebar — it is assigned at launch and changes between runs.

Interactive API documentation is served at `http://127.0.0.1:PORT/docs` (and `/redoc`). Those pages are always available, but the `/sdapi/v1/*` routes only appear in them once `--api` is enabled.

### Common endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/sdapi/v1/txt2img` | Generate an image from a prompt |
| `POST` | `/sdapi/v1/img2img` | Generate an image from an input image |
| `GET`  | `/sdapi/v1/sd-models` | List installed checkpoints |
| `GET`  | `/sdapi/v1/samplers` | List available samplers |
| `GET`  | `/sdapi/v1/progress` | Poll progress of the running job |
| `GET`/`POST` | `/sdapi/v1/options` | Read or change settings, including the active checkpoint |
| `POST` | `/sdapi/v1/interrupt` | Cancel the running job |
| `POST` | `/sdapi/v1/png-info` | Read generation metadata out of a PNG |

`txt2img` returns JSON with an `images` array of base64-encoded PNGs (no data-URI prefix) and an `info` field containing a JSON **string** — note it must be parsed separately, as shown below.

### curl

```bash
# List installed checkpoints
curl http://127.0.0.1:7860/sdapi/v1/sd-models

# Generate an image and write it to disk
curl -X POST http://127.0.0.1:7860/sdapi/v1/txt2img \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "a pencil drawing of a bear",
    "negative_prompt": "blurry, low quality",
    "steps": 25,
    "width": 1024,
    "height": 1024,
    "cfg_scale": 7,
    "sampler_name": "Euler"
  }' | jq -r '.images[0]' | base64 -d > output.png
```

### Python

```python
import base64
import requests

BASE = "http://127.0.0.1:7860"

response = requests.post(
    f"{BASE}/sdapi/v1/txt2img",
    json={
        "prompt": "a pencil drawing of a bear",
        "negative_prompt": "blurry, low quality",
        "steps": 25,
        "width": 1024,
        "height": 1024,
        "cfg_scale": 7,
        "sampler_name": "Euler",
    },
    timeout=600,
)
response.raise_for_status()
result = response.json()

with open("output.png", "wb") as f:
    f.write(base64.b64decode(result["images"][0]))

# `info` is a JSON-encoded string, not an object
import json
info = json.loads(result["info"])
print("seed:", info["seed"])
```

### JavaScript

```javascript
import { writeFile } from "node:fs/promises";

const BASE = "http://127.0.0.1:7860";

const response = await fetch(`${BASE}/sdapi/v1/txt2img`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    prompt: "a pencil drawing of a bear",
    negative_prompt: "blurry, low quality",
    steps: 25,
    width: 1024,
    height: 1024,
    cfg_scale: 7,
    sampler_name: "Euler",
  }),
});

if (!response.ok) throw new Error(`${response.status} ${await response.text()}`);
const result = await response.json();

await writeFile("output.png", Buffer.from(result.images[0], "base64"));

// `info` is a JSON-encoded string, not an object
const info = JSON.parse(result.info);
console.log("seed:", info.seed);
```

### Switching checkpoints

The active checkpoint is a setting rather than a per-request parameter. Use the title from `/sdapi/v1/sd-models`:

```bash
curl -X POST http://127.0.0.1:7860/sdapi/v1/options \
  -H "Content-Type: application/json" \
  -d '{"sd_model_checkpoint": "sd_xl_base_1.0.safetensors [31e35c80fc]"}'
```

Changes made through `/sdapi/v1/options` are **persisted to Forge's config**, so they outlive a restart.

## Troubleshooting

Pinokio writes every script's terminal output to `logs/api/<script>/`, one file per shell step, with `latest` pointing at the most recent. Start there.

### `SSLError: [ASN1: NOT_ENOUGH_DATA]` on the first generation

The first generation downloads a small VAE-approx model used for live previews. If Python cannot parse your Windows certificate store, that download fails and the whole request returns a 500:

```
Downloading VAEApprox model to: ...\models\VAE-approx\vaeapprox-sdxl.pt
ssl.SSLError: [ASN1: NOT_ENOUGH_DATA] not enough data (_ssl.c:4030)
```

The failure is in `ssl.create_default_context()` itself, which loads the Windows cert store before consulting `SSL_CERT_FILE`, so setting `SSL_CERT_FILE` or `REQUESTS_CA_BUNDLE` does **not** help. Generation itself is unaffected — only the preview model download.

Either of these resolves it:

- **Pre-place the file.** Download `vaeapprox-sdxl.pt` (and `model.pt` for SD1.5 checkpoints) from the [Automatic1111 v1.0.0-pre release](https://github.com/AUTOMATIC1111/stable-diffusion-webui/releases/tag/v1.0.0-pre) into `app/models/VAE-approx/`. Forge only downloads when the file is missing.
- **Turn off live previews.** In **Settings → Live previews**, uncheck *Show live previews of the created image*.

### The Web UI tab does not appear

Check `logs/api/start.js/latest` for a Python traceback. If Forge crashed during startup, Pinokio will keep reporting `starting` and no URL will be published.

### Starting fails after a previously interrupted install

A failed clone can leave an empty `app/repositories/stable-diffusion-stability-ai` directory behind, which stops Forge from ever re-cloning it. `start.js` detects and clears this automatically, but if you hit it in another checkout, delete that folder and start again.

## Notes on this launcher

- `Stability-AI/stablediffusion` was taken down upstream, so `STABLE_DIFFUSION_REPO` points at a mirror carrying the same pinned commit (`cf1d67a6`). Git verifies the hash on checkout, so the resulting tree is identical to the original.
- NumPy and OpenCV are pinned (`numpy==1.26.2`, `opencv-*==4.8.0.76`). Newer OpenCV requires NumPy 2, which breaks the NumPy 1.x ABI that this build of torch and scikit-image were compiled against.
- The Web UI URL is derived from a port reserved by Pinokio and passed to Forge via `GRADIO_SERVER_PORT`, rather than scraped from the server's output.
